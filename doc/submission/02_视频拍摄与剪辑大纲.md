# 安芯智视演示视频拍摄与剪辑大纲

成片目标为 **2 分 50 秒，即 170 秒**，留出 10 秒余量。采用横屏 16:9，MP4 容器、AVC/H.264 视频编码，文件小于 300 MB。作品名称暂用“安芯智视 视觉跟踪云台系统”，可在定稿时统一替换。

视频的主线是：**摄像头看见现场，FPGA 处理与定位，云台根据目标调整取景。** 用实际画面讲清楚这条链，再展示图像处理和交互能力。

## 一 参考视频如何借鉴

已查看提供的参考视频关键画面，播放器显示总长约 1 分 42 秒。约 0～24 秒以作品标题、分块介绍、控制板和显示部件说明为主；约 30～90 秒展示桌面实物、云台动作和手机显示；约 99 秒进入结束页。这里是抽样画面分析，未逐字转录音轨。

可借鉴“先认识系统，再看操作，再看结果”的顺序，以及操作者、云台、显示端同框的镜头。我们的方案缩短纯标题页，将更多时间分给真实功能。参考片中的姓名等内容不沿用，既不使用其画面充当本作品成果，也不沿用其三轴、体感和无线图传功能描述。

## 二 拍摄前的操作准备

成片只呈现作品功能、实际操作和有意义的性能。版本号、构建名称、哈希与内部失败记录留在内部依据文件，不放进旁白、字幕或报告画面。

### 板载操作速查

| 项目 | 正确操作 |
| --- | --- |
| 白平衡 | SW1 自动 / 锁定已应用增益；先等待颜色稳定再锁定 |

| 自动跟随 | SW3 开启 / 关闭；关闭时仍可做定位和显示框线 |
| 方向键 | SW4 开启后 K4 左、K3 下、K2 上、K1 右 |
| 手动与自动关系 | SW4 只是切换键用途；按方向键时临时接管，松开等待新有效结果恢复自动 |
| 模式切换 | SW4 关闭时，K1 下一模式、K2 上一模式 |
| 模式编号 | 11 人脸、12 模板、13 色区、14 运动；全范围 00～14 连续循环 |
| 重新选取 | 模板 / 色区模式按 K4；人脸模式自动检测，不需要中心取样 |

模式名称以本表为准。SW4 开着也不代表自动一定停止；要拍固定机位，明确关闭 SW3 并停止方向键输入。

先完成一次不计入成片的排练：图像正常 → 全部模式可切换 → 人脸/色区出现有效框 → 云台方向正确 → 目标丢失保持 → 手动接管和恢复。屏幕若有外部控制权，先用实体按键或开关变化接回本地，再核对有效状态。

## 五 现场拍摄方法

### 画面安排

主机位保持固定，将被跟随目标、云台和显示器尽量放在同一画面中；必要时用 HDMI 采集画面作右上或右下的小窗。这样能同时证明“目标在动”“摄像头在跟随”“显示结果来自现场”。采集卡、拍摄手机或录屏电脑属于记录设备，勿将其介绍成在线推理设备。

拍摄显示器时先测试条纹和闪烁。锁定拍摄设备的曝光、对焦与白平衡，调整快门以减轻刷新条纹。若用 30 fps 拍摄，不能据此测出系统是否持续输出 60 个不同图像帧；“720p60”只按系统配置和实际验证口径表述。

颜色跟踪优先使用哑光目标和不同色背景，避免大面积同色背景、镜面白化与逆光。模板跟踪使用清晰、非重复纹理，适度移动。运动检测必须固定机位，等参考就绪后开始动作。

### 剪辑与字幕

每次切换模式留下约 2～3 秒稳定画面。跟随、丢失保持和重捕的关键证明段使用正常速度，保持动作因果关系；不得删掉恢复等待再声称“瞬间重捕”。如等待较长，可完整保留该过程、压缩其他段落，或加真实计时字幕。

字幕以“做了什么、看到了什么”为主，每屏一到两行；技术词只保留 FPGA、HDMI、PWM 等必要内容。把图像处理结果标成“摄像头实拍”，把历史 RTL 图片标成“仿真输出”，避免混用。视频中的框图只保留五六个模块，不照搬技术文档的详细图。

配音用正常语速，背景音乐低于人声，可保留一小段按键和舵机现场声。转场以直接切换和短淡入淡出为主，避免长片头和重复结束动画。

### 不纳入成片的信息

逐项检查片头、片尾、字幕、配音、服装、桌牌、屏幕桌面、浏览器标签、工程路径、报告页眉及文件属性，去除学校名称、校徽、指导老师姓名及其他与作品无关的信息。片头片尾仅保留作品名与功能描述。保留与作品有关的器件和平台标识，如安路 Logo。

不在旁白中宣称“身份识别”“60 FPS 人脸识别”“零延迟”“任意目标追踪”“全天候稳定”或未经独立测量的精度、功耗。OSD 耗时有自己的测量边界，不能直接称为摄像头到屏幕的总延迟。

## 六 导出与验收

### 剪辑软件导出设置

| 选项 | 设置 |
| --- | --- |
| 容器 | MP4 |
| 视频编码 | AVC / H.264，明确不要选 HEVC/H.265 或 AV1 |
| 分辨率 | 1920×1080；若素材主要为 720p，可直接用 1280×720 |
| 画幅 | 16:9，横屏 |
| 帧率 | 固定 30 fps；60 fps 原片可保留，但不是提交必需条件 |
| 视频码率 | 目标 8 Mb/s，最大约 10 Mb/s |
| 像素格式 | 8-bit YUV 4:2:0，常见软件中为兼容性选项 |
| 音频 | AAC，48 kHz，约 160 kb/s |
| 成片长度 | 170 秒，最终必须小于 180 秒 |
| 文件大小 | 建议小于 250 MB，硬性要求小于 300 MB |

按平均视频 8 Mb/s、音频 0.16 Mb/s 和 170 秒估算，主体数据约 **173.4 MB**，另加少量容器开销。码率估算不代替对最终文件大小的检查。

可在剪辑软件直接完成上述导出。若后续使用 FFmpeg，可对已剪好的母版执行下列命令；本次没有执行视频剪辑或转码。

```powershell
ffmpeg -i "master.mp4" -map 0:v:0 -map "0:a?" -c:v libx264 -preset medium -crf 20 -maxrate 10M -bufsize 20M -pix_fmt yuv420p -r 30 -c:a aac -b:a 160k -ar 48000 -movflags +faststart -map_metadata -1 "安芯智视_演示视频.mp4"
```

此命令不负责把超长母版剪成三分钟，也不掩盖片头片尾中的身份信息。先完成 170 秒剪辑，再转码。可用以下命令检查实际输出属性：

```powershell
ffprobe -v error -show_entries format=duration,size:stream=codec_type,codec_name,codec_tag_string,width,height,pix_fmt,avg_frame_rate -of json "安芯智视_演示视频.mp4"
```

确认视频流 `codec_name=h264`，常见 MP4 标签为 `avc1`；`duration<180`，文件大小保守按 `<300000000` 字节验收。完整播放一次，检查开头、中间、结尾、音画同步和字幕。导出后再次确认文件属性中的标题、作者及备注不含无关信息。

## 七 素材不足时的替换方案

- 串口屏还未调通：本片只用实体按键和 HDMI 状态展示，不增加总时长。
- 人脸闭环尚不稳定：保留固定机位定位片段，使用已经实拍验证的色区功能展示云台动作，旁白对应修改。
- 模板重捕时间过长：保留纹理选取与跟踪，将重捕放在补充测试中，删去主片对应恢复结论。
- 运动检测未稳定：用已验证的锐化/模糊对照或手动接管补足该段，主片不展示未通过功能。
- 拍摄采用不同实现：先更新操作表、模式编号和技术文档中的版本指标，再拍摄；不混接不同版本画面制造单一版本效果。
