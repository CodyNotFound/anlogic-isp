# 安芯智视 视觉跟踪云台系统

## 摘要

本作品面向桌面自动取景、交互展示与嵌入式视觉实验，基于安路 PH1P35 FPGA 和 HX1P35A 开发板，构建摄像头采集、图像处理、目标定位、视频显示与两轴云台控制一体化系统。SC500CS 摄像头通过双通道 MIPI CSI-2 输出 RAW10 数据，经图像信号处理和 DDR2 帧缓存后，以 1280×720@60 Hz 视频时序输出至 HDMI 显示设备。图像处理链包含黑电平校正、镜头阴影校正、去马赛克、自动白平衡与色调处理，并支持自动曝光及白平衡参数锁定。

系统提供十五种运行模式，覆盖基础色彩显示、空间滤波、边缘提取、卡通化、人脸定位、模板跟踪、颜色区域检测与固定机位运动检测。人脸定位采用公开 YuNet 模型的 FPGA 定点实现；模板、色区与运动分析按模式复用片上存储。有效目标位置经控制逻辑转换为两路舵机 PWM，支持自动跟随、方向键临时接管和目标丢失保持。中文屏幕信息显示运行模式、目标状态、视频帧率、处理耗时及云台指令位置，串口接口支持外部屏幕控制与状态回传。

项目围绕有限资源开展流水线划分、定点算术简化和存储复用，并建立算法参考、RTL 仿真、布局布线时序分析与构建归档流程。系统采用流水线视频处理与独立任务调度，普通图像模式应用链帧首计数约 0.00023 ms，人脸核心计算约 266.56 ms；模板单次搜索和色区计算参考耗时分别约 14.85 ms、6.27 ms。作品的主要贡献在于将图像处理、硬件视觉推理和执行机构控制整合到同一 FPGA 平台，形成可观察、可交互、可复现的视觉系统。

**关键词：** FPGA；图像信号处理；定点神经网络；目标跟踪；两轴云台

## 第一部分 作品概述

### 1.1 功能与特性

系统从摄像头获取现场画面，在 FPGA 内完成图像处理、目标分析和显示叠加。用户可切换灰度、锐化、模糊、边缘和卡通等模式，观察同一场景的不同表达；也可进入人脸、模板或色区模式获取目标位置，驱动两轴云台调整取景方向。运动模式用于固定机位下的画面变化检测。实体按键、拨码开关和串口控制接口共同构成交互入口，支持目标重新选取、自动曝光与白平衡锁定、自动跟随使能及方向控制。在线图像分析由 FPGA 执行，无需上位机提供检测坐标。

【插图 1：系统正面实物全景。包含开发板、摄像头、云台、HDMI 显示器和独立舵机电源；标注各部件名称。】

### 1.2 应用领域

本作品适用于桌面人物取景、展品跟随、视觉算法交互演示与 FPGA 教学实验。人物场景可观察人脸定位与云台联动，具有鲜明颜色或纹理的物体可用于比较色区与模板跟踪的适用条件，固定机位场景可展示运动区域提示。图像处理模式提供直观的算法效果对照，便于理解像素流水线与图像特征之间的关系。系统同时保留模块化接口，可作为后续视觉终端研发的验证平台。

### 1.3 主要技术特点

视频通路采用流式处理与帧缓存相结合的结构，将持续视频输出与较低更新率的分析任务分离。ISP 使用定点增益、网格插值和帧级统计，兼顾图像校正与硬件代价。人脸分析将公开模型转换为定点算子和片上参数存储，模板、色区及运动任务复用互斥模式下的存储空间。云台控制只消费新的有效定位结果，通过限幅、分步更新和丢失保持约束动作。系统以中文 OSD 呈现状态，并通过逐值仿真、源文件校验与最终路由报告建立验证依据。

### 1.4 主要性能指标

| 项目 | 指标 |
| --- | --- |
| 输出 | 1280×720@60 Hz |
| 普通处理 | 约 0.00023 ms |
| 人脸核心 | 约 266.56 ms |
| 模板搜索 | 约 14.85 ms |
| 色区计算 | 约 6.27 ms |
| 模式 | 15 种 |
| 云台 PWM | 双路，50 Hz，1 μs 粒度 |

耗时按 75 MHz 计数折算；普通处理为应用链帧首计数，其余为任务计算参考值，测量范围见 3.3。

### 1.5 主要创新点

1. 将图像校正、定点人脸定位、多类目标分析与两轴控制整合为单 FPGA 视觉链路。
2. 利用任务互斥关系共享 CNN 特征存储，降低多模式系统的片上存储开销。
3. 将结果新鲜度、动作限速、丢失保持和人工接管纳入统一控制流程。
4. 将中文状态显示、板载按键与可选串口屏统一到同一交互逻辑。

### 1.6 设计流程

从官方摄像头显示例程建立基线，依次开展 RAW 数据检查、黑白场标定、ISP 校正、视频传输修复和模式交互设计；随后接入目标分析与云台控制，完成 CNN 定点化、资源复用和显示优化。通过参考算法、RTL 仿真与整机实现检查计算正确性和实时性，再结合实物操作完善交互体验。

## 第二部分 系统组成及功能说明

### 2.1 整体介绍

系统由摄像头与采集接口、图像校正与缓存、应用图像处理、视觉分析、显示叠加、交互控制和云台执行七个部分组成。平台层处理摄像头配置、MIPI 接收、DDR2 访问及 HDMI 输出；应用层在视频像素时钟域执行模式选择、像素算法、目标分析与界面叠加。自动曝光根据图像亮度统计调整传感器参数，自动白平衡在图像处理链内部更新颜色增益，两者均可锁定当前参数。

【插图 3：系统总体框图。按下列连接绘制，图内用不同线型区分图像数据、控制信号和状态反馈。】

```text

    ▼

    ▼
DDR2 帧缓存与视频读出
    ▼
应用图像处理 ──────────→ 中文 OSD 与标注 ──→ HDMI 显示
    │                         ▲
    └→ 缩采样与互斥分析任务 ──┤
       人脸 / 模板 / 色区 / 运动│
              │ 有效目标位置   │ 状态
              ▼               │
       目标选择与云台控制 ─────┘
              │ 双路 PWM
              ▼
          水平与俯仰舵机

实体按键 / 拨码 / 串口屏 → 模式、取样、参数锁定及控制权管理
```

视频流持续输出，分析单元按自身处理能力获取图像并发布结果。该结构避免将视频显示频率等同于分析速度，也便于在目标暂时不可用时继续显示画面并保持云台位置。

本作品基于现成开发板进行系统集成，主要设计工作集中在自有 RTL、图像校正、分析任务、控制协议与验证工具。开发板、传感器及官方基础 IP 的来源在参考文献中注明。

### 2.3 软件系统介绍

#### 2.3.1 软件整体介绍

本系统的在线功能主要由 Verilog RTL 实现。离线 Python 工具负责标定数据处理、模型转换、参考结果生成及报告检查；PowerShell 脚本负责仿真与 TD 构建。PC 用于开发和验证，不参与板端在线目标推理。串口屏是交互终端，连接与否不改变 FPGA 内部执行图像分析的架构。

工程以平台与应用分层组织：平台层负责摄像头、缓存及视频传输；应用层负责处理模式、分析任务、状态叠加和云台控制。模块之间通过明确的数据有效、帧首、行尾、握手和结果有效信号交接。

#### 2.3.2 软件各模块介绍

**一 图像校正与标定**

图像校正首先对 RAW10 数据进行黑电平减除，将低于黑电平的值钳位到零。镜头阴影校正采用 17×13、共 221 个网格节点，对 Bayer 四颜色位置存储增益并进行双线性插值。增益使用 Q2.10 定点表示，像素乘增益后按范围饱和，防止溢出回绕。校正后的 RAW 数据进入 BGGR 去马赛克模块，随后执行白平衡和色调处理。

白平衡通过帧级颜色统计和灰点候选筛选估计增益，并约束增益变化，降低场景波动引发的颜色跳变。SW1 控制自动更新或保持已应用的红、蓝通道增益。曝光控制根据亮度统计调整传感器，SW2 关闭自动更新时保持已有曝光状态。锁定意味着停止更新参数，而非旁路已有校正。

研发中使用遮光场与均匀照明场分析黑位及空间色偏。原始采集数据只有在帧头、长度、校验和及像素范围满足约定后，才适合用于多帧统计。全局颜色增益和空间阴影校正解决不同问题，不能用一次全局白平衡代替镜头与模组标定。

【插图 8：固定曝光和固定机位下的白场校正前后对照，以及中心到边缘的 R/G、B/G 分布。注明照明、曝光和校正条件。】

**二 视频缓存与数据一致性**

采集与显示处于不同节拍，DDR2 帧缓存承担二者之间的速率解耦。像素数据经过并行排列、打包、写入和读出再进入显示通路。实现中，帧边界必须与对应像素一起传递，读写状态只在有效握手后推进，行尾和停顿不能造成像素丢失或顺序交换。

项目围绕相机时钟桥、帧首传递、像素顺序、DDR 仲裁和反压开展专门检查。验证使用可判定像素序列和完整帧输入，比对实际输出的位置与数值。显示出 Logo 仅说明部分输出链路有效，摄像头画面正确还需检查采集、ISP、缓存和读出各阶段。

**四 FPGA 定点人脸定位**

系统基于 YuNet 轻量人脸检测网络[3-4]，完成适合 FPGA 的定点化、算子调度、存储布局及推理电路设计。使用公开预训练参数作为起点，针对摄像头输入完成量化校准与硬件适配。人脸位置由板端完整推理产生，PC 不参与在线检测。

网络由特征提取骨干、多尺度特征融合和检测头组成。输入为 160×90 的 BGR 缩采样图像，补零至 160×96。骨干使用普通卷积、逐点卷积、深度卷积及池化提取特征；特征融合通过上采样与相加，将不同层次的信息传递至三个检测尺度。步长 8、16、32 分别对应 20×12、10×6、5×3 的预测网格，共 315 个候选位置。

每个尺度的分类、目标性和边框回归分支共同产生人脸候选。解码单元结合分数筛选目标，将位置映射回 1280×720 画面，输出中心及框线，供显示和云台控制使用。当前部署保留定位所需分支，不运行五点关键点分支。

```text
160×90 BGR 图像 → 补零至 160×96
    ↓
轻量卷积骨干：普通卷积 / 逐点卷积 / 深度卷积 / 池化
    ↓
多尺度融合：上采样 + 特征相加
    ├→ 步长 8：20×12 网格 ──┐
    ├→ 步长16：10× 6 网格 ──┼→ 分类 + 目标性 + 边框回归
    └→ 步长32： 5× 3 网格 ──┘
                               ↓
                       分数筛选与坐标解码
                               ↓
                       显示框线与云台控制
```

硬件采用 int8 权重与中间特征、int32 偏置及累加，输入像素保持无符号 0～255。网络降低为 55 个硬件操作，共包含 47 个卷积层，使用约 49.33 kB 有效权重；四路共享乘加单元以 4 个 DSP 执行卷积运算，避免逐层展开。通过通道移位、舍入和饱和处理保持定点数值一致，通过四银行特征存储、行缓存和像素缓存降低访存代价。

单次核心推理为 19992365 个时钟，按 75 MHz 计算约 266.56 ms。视频通路与检测任务独立运行，因此显示可保持 1280×720@60 Hz，而定位结果按任务完成节拍更新。云台根据新的有效结果分步调整，兼顾显示连续性与运动控制。

**五 模板 色区与运动分析**

模板模式从中心取样区域建立梯度模板，结合有限角度和尺度候选进行匹配。目标丢失后保留模板，通过分块搜索扩大重捕范围，并在再次确认后输出位置。重复纹理、明显尺度变化或严重姿态变化可能导致匹配失败。

色区模式对中心选取区域估计颜色特征，使用归一化色度、区域连通性和位置面积关联寻找目标。它适合颜色明确、与背景可区分的物体；相似颜色的不同物体可能产生歧义，高光导致目标颜色消失时不能保证持续跟踪。

运动模式在固定机位下比较相邻图像的亮度变化，并对邻域支持、变化规模和连续确认设置条件。大范围亮度变化和云台指令变化会影响参考有效性，因此运动模式不承担自动云台跟随。该模式检测画面变化，不进行物体类别识别。

人脸、模板、色区和运动任务互斥运行，共享闲置的 CNN 特征存储空间。切换模式时重置任务状态与存储所有权，避免旧模式数据干扰新模式。

【插图 11：模板选取和重捕、色区框选、固定机位运动提示各一张实拍，附相应输入条件。】

**六 云台控制与交互**

控制模块接收目标有效标志、目标中心及结果更新事件，根据中心偏差计算有界的 PWM 修正量，并分步逼近指令位置。旧结果不会被反复用于累加运动；目标丢失、自动关闭或人工接管时取消待执行动作并保持指令位置。

两路 PWM 的周期为 20 ms，指令粒度为 1 μs。显示界面的 H/V 值表示控制器发出的脉宽，并非传感器测得的实际角度。闭环响应受检测周期、舵机速度、机械惯量和目标运动共同影响，需通过实物测试评估。

| 控件 | 功能 |
| --- | --- |
| SW1 | 白平衡自动更新或锁定当前增益 |
| SW2 | 自动曝光更新或锁定当前曝光状态 |
| SW3 | 自动云台跟随使能，检测与显示仍独立运行 |
| SW4 | 切换四键为方向用途；按键期间临时接管 |
| K1 / K2 | 非方向用途时，模式递增 / 递减 |
| K4 | 非方向用途时，模板或色区重新取样；运动模式重建参考 |
| K4 / K3 / K2 / K1 | 方向用途时，左 / 下 / 上 / 右 |

SW4 开启但没有方向键输入时，不会持续禁止 SW3 自动跟随；方向键松开后等待新的有效定位结果恢复自动。串口屏使用校验报文设置模式、功能和方向。本地按键或开关变化可接管控制，周期查询不会反复抢回控制权，远端方向指令具有 250 ms 到期停止机制。板载按键、拨码和 HDMI 中文提示已经构成完整的独立操作入口；接入串口屏后，可用更直观的页面完成模式选择和状态查看，无需改变内部视觉处理链路。

**七 状态显示与工程验证工具**

中文 OSD 显示模式名称、分析状态、坐标、帧率和云台指令位置，并保留安路 Logo。普通图像模式显示应用视频输入帧首到处理输出帧首的链路耗时，分析模式显示任务计算耗时。二者的测量起点和终点不同，均不等同于摄像头曝光到显示屏发光的端到端延迟。

验证流程依次检查参考算法与定点运算、RTL 输出、完整应用链路、综合资源、布局布线时序和归档一致性。验证工具检查输入数据、计算结果与显示状态的一致性，使优化前后的功能能够进行可重复比较。

## 第四部分 总结

### 4.1 可扩展之处

后续可建立独立的人脸与跟踪测试集，量化不同光照、尺度和姿态下的表现；完善镜头及传感器标定，提高跨场景色彩一致性。后续扩展可继续通过存储调度和计算复用提高资源利用率。控制部分可结合机械参数和位置反馈完善动态性能，并完成端到端延迟与功耗测量。串口交互可扩展为配置与测试入口，帮助形成可重复的现场操作流程。

### 4.2 心得体会

研发过程中，我们逐步认识到，视觉系统的效果取决于算法、数据通路和执行机构之间的配合。早期面对画面偏色和明暗不均时，仅调整显示端颜色参数难以确定原因。通过检查原始图像、黑位及不同位置的通道比例，才能区分全局颜色增益与空间阴影问题，使校正具有依据。

视频链路的调试也表明，局部画面正确不代表整个系统可靠。Logo 能够显示时，摄像头采集或缓存仍可能存在异常；静态图片正常时，帧首处理、反压或像素排列问题仍可能在连续输入中暴露。因此，我们使用可判定的数据模式、完整帧输入和异常时序测试，把错误定位到具体边界，而非仅凭屏幕观感修改参数。

在将人脸网络落地到 FPGA 时，资源限制促使我们重新考虑每一处算术与存储开销。定点化不仅需要压缩位宽，还要明确舍入、溢出与激活的规则；存储复用也必须同时处理所有权和模式切换。逐算子、逐像素的参考比对，使资源优化能够在保持行为一致的前提下进行。

云台联动进一步说明，画面流畅、定位有效和机械跟随平稳是不同目标。分析结果更新较慢时，重复使用旧坐标可能累积过量运动；目标丢失时继续追逐旧位置也会偏离实际场景。我们为结果更新、限速、保持和人工接管建立明确规则，并把最终闭环效果留给实物验证。

项目使我们建立了从算法参考到硬件输出的完整验证方法。逐值比较帮助判断计算是否正确，时序分析帮助判断电路能否按目标频率运行，现场操作则检验交互和控制是否自然。将三者结合，才能把多个独立功能整合为可理解、可操作的视觉作品。
