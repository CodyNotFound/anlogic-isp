# v59～v63 人脸框回退核对

用户确认以v59～v63为“修复云台过冲之前”的基准，而不是更早LBP版本。

核对历史文件并去除换行格式差异后：v59、v63、当前版的采样器、计算程序、模型权重一致；v61网络修改增加外部32位读出，仅服务共享RAM，没有改推理状态转移。v64相对v63的相机适配器只增加inference_cycles与capture_started输出；画框模块只有2像素边改3像素边、1像素十字改3像素十字，没有加坐标平滑、等待帧或降低显示更新率。

保存实际文件hash见reports/display_v73/history_hashes.json。使用实际v63画框模块与当前模块回放90次SOF、6次稀疏定位，框坐标、保持、丢失、视频限定信号逐拍一致，日志history_replay.log。该回放不能证明上板时摄像头输入、光照、云台运动或实际烧录bit一致；目前没有由源代码复现用户观察到的退化，不能宣称问题已经完全定位或修复。

v44确实存在局部搜索/梯度模板短时补位，但它不是用户指定的基准，本轮不接入这个额外跟踪器，也不加坐标动画掩盖检测等待。

候选v73改的是实际CNN访存等待：对1x1像素缓存预取权重；连续通道组预取下一组权重/激活或行缓存地址，仅在当前beat已被MAC接受且不跨通道末端时启用。结果与原55层、659460个激活字节逐位一致。网络计算周期19992365降为17828660（约10.8%），模型权重、判断阈值、坐标解码、舵机参数不改。实际检测周期仍包括采样/等待帧/解码，不能将理论计算率当作实际检测FPS，更不能写成60FPS人脸检测。
